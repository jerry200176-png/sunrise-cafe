# 客人訂位草稿整合

#518 的退款申請說明、#522 的減少動態偏好和錯誤定位、#524 的分頁內未知結果保護同時修改訂位表單；個別 CI 通過不能證明交互合併後仍正確。這個整合保留三者原有行為及其限制：提交未確認時同時段在同一分頁不可重送並提供查詢／聯絡，舊請求的延遲回覆不覆蓋新選擇；錯誤提示在 React 掛載後依目前動態偏好捲動，且不搶客人焦點；明確的非 408 類 4xx 拒絕可解除對應時段保護。客人改選後若舊請求才回覆，不為舊回覆移動畫面。

503／408、網路失敗及成功但未取得有效代號均是未知結果，顯示查詢及聯絡的保守提示，而不是直接顯示伺服器的錯誤文字；這是 #524 相對 #522 原有 503 測試的行為變更。整合測試應同時確認未知狀態、不能重送、查詢入口、焦點及即時／平滑定位，並確認改選後舊回覆不影響新草稿。退款文案及三語沿用 #518，不修改退款政策或付款流程。

參考及根因見各原設計：[退款說明](2026-11-01-refund-disclosure.md)、[動態偏好](2026-11-booking-reduced-motion.md)、[未知結果保護](2026-11-booking-uncertain-guard.md)。此功能並非跨分頁、跨裝置或伺服器端冪等；清除分頁儲存或切換裝置不受保護。個別 PR 和此候選的 CI 通過也不解除現有 release hold；未接觸正式訂位或部署。

提交請求收到標頭後仍需在有限時間內讀取完整本文；本文逾時同樣視為結果未知並保留同分頁鎖。送出期間客人修改表單內容或離開步驟時，同步更新頁面內版本；即使內容改回或返回同一時段，舊成功與拒絕回覆也不導向、不清除新草稿或顯示過期錯誤。明確拒絕仍會解除該選擇的鎖；未確認／成功則保留查詢入口。此版本不跨分頁、不存客人身分，不提供伺服器冪等。

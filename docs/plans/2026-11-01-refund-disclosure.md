# 已付訂金退訂申請：對客說明

## 現況與根因

搜尋訂位、完成頁、查詢頁、`cancel-refund-policy` 和 `/api/refund-request`：未付訂金的客人可在開始前至少 24 小時自行取消；已付訂金的客人不能透過現有查詢頁自行取消。雖然有退款申請 API，客人查詢頁目前沒有送出該申請的介面，資料表是否存在也未驗證，因此不能向客人承諾線上申請已可使用。現有查詢頁舊翻譯另寫「訂金不予退還」，與使用者採納的申請方向不符；症狀是客人在訂位前和查詢時看不到一致且可執行的資訊，根因是政策文字未隨營運決策統一。

## 方案及限制

使用者已選擇 #211 FD-4 的建議：訂位開始前至少 48 小時可申請退款，不足 48 小時由店員審核。訂位前、完成頁和已付訂金的查詢頁顯示這一方向，要求以電話或 LINE 聯繫，並明確說明退款金額與結果需店家確認、非自動退款。同步修正取消 API 可能顯示的錯誤訊息及中、英、日版的「一律不退款」舊文字。未付訂金維持現有 24 小時線上自行取消條件。

不更動取消資格、款項、資料庫、付款或退款 API 的寫入行為；不承諾一定全額、何時到帳或電話／LINE 一定即時收到。不可只呼叫既有申請 API 即表示申請已成功：其 DB 表狀態、重複送出保護與實際後台追蹤未驗證。其他政策（權限、證據、舊資料、回退和退款上限）仍為待形成具體方案的假設；不從這次確認推導。

替代方案是加上線上申請介面，但目前缺少正式 DB、店員收件及結果驗證，先不暴露尚不能確認可靠的流程。將這些條件留在 #211 和退款 PR 待辦中；本 PR 只改善如實揭露，不宣稱解決退款流程或關閉議題。

## 驗證與回退

測試已付訂金的 48 小時邊界仍不允許自動取消；三種語言的訂位與查詢提示均包含時限和聯絡方式。以既有訂位瀏覽器測試確保選擇、提交及查詢不受影響。回復本 PR 可還原原文字，沒有資料庫遷移或對真實付款的操作。

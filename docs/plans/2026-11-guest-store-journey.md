# 客人整店 3D 與訂位體驗

## 問題與現況
客人需要理解整間店與各包廂的位置，再看真實照片選擇。現在每張卡片各有獨立 3D 圖、無法看整店；目前選房完成後才輸入人數，容量不符會在最後才發現。分店及空檔請求失敗也可能被誤當空資料，切換時較慢的回應可能覆蓋新選擇。

搜尋 `RoomPreview`、`floor-plan`、room image、availability、booking、guest count、waitlist 與 open PR；重用 `/book` 卡片和照片、明確名稱對應、`DAAN_FLOOR_PLAN`、既有五個 Blender GLB、WebGL fallback、訂位 API、訂位草稿與容量驗證。Open PR 無重疊。#351 的 LINE 查詢 token 已由 #352 合併，另以現有測試確認後處理 issue；#476 與 #487 仍有其他未完成範圍，不直接結案。

## 方案與架構
1. 用 Blender 將五間既有模型按大安平面圖組成一個可重建的店內 GLB，加入入口、走道和櫃台等概略空間。未知或估算部位清楚標示「示意」，不聲稱照片級重建，不猜測其他分店。保留原模型與生成程式。
2. 在選房頁提供一個按需載入的整店 3D 視圖；點 3D 包廂或可鍵盤操作的標籤會定位、聚焦對應照片卡片，客人仍由原照片卡片查看容量、價格、空檔與選擇。客滿時沿用原候位。僅接受明確匹配的分店及房名，重名/不明不得猜測。圖片及非 3D 流程持續可用；模型失敗、無 WebGL、手機與鍵盤均有替代入口。
3. 選房頁提供選填人數提示，早於時段/個資顯示包廂是否適合；沿用既有草稿、容量規則與最終驗證，不變更付款、取消、權限或通知政策。
4. 加固必要的客人 GET：區分非 2xx、格式錯誤、空資料；以請求生命週期阻止舊分店/日期/房間資料回填，允許安全重試，絕不自動重送訂位寫入。候位確認時間統一採 Asia/Taipei，避免海外裝置顯示錯誤。

替代方案：保留每卡獨立 3D，不能理解整店關係；以示意圖完全取代照片，會失去現場真實參考；全店自動載入會增加手機頻寬與 GPU 壓力。此次保留照片卡片與按需載入整店模型。

## 驗收、部署與回滾
桌機及手機可在一個場景看全店、透過滑鼠/觸控/鍵盤選擇正確包廂，照片及原選房、候位、時段、送出流程可用；不匹配/重名與無法使用 WebGL 時不產生錯誤選房。客滿不得繞過候位。切換篩選、日期、分店及失敗重試時不顯示過期資料。以本地模擬資料測完整流程、GLB 實際載入與互動；不使用正式客資或建立真實訂位。沿現有 CI、獨立審查與部署；回滾此 PR 即可，無資料庫遷移。

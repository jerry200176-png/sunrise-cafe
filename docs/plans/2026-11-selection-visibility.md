# 訂位清單選取狀態（#493 局部）

## 問題與盤點
後台批次複製訂金訊息沿用現有的 `ReservationList`：搜尋 `indeterminate`、`selectedReservationIds`、`全選目前列表`、批次工作台及其瀏覽器測試，確認已有子項、全選目前清單、總筆數、分店切換清除，以及需額外按鈕開啟的批次預覽。根因是父方塊只表示全選或未全選，而篩選／分頁切換會保留清單外的已選資料，沒有表明其數量。

## 方案
在現有核取方塊使用原生 `indeterminate`；計算目前清單與清單外的已選筆數，當清單外非零時顯示明確提示。保留跨篩選的既有選取和手動清除；不因勾選自動操作、不修改批次 API、權限、資料或排序。替代方案是每次切換篩選時清除：可能讓使用者失去有意選取，故不採用。空清單時父方塊停用，清單外選取仍可清除或預覽。

## 驗收與部署
無選取／部分／全選與空清單的狀態正確；以鍵盤 Space 選取；篩選切換準確標示隱藏數，清除及切分店能清除既有選取；開啟批次預覽仍使用使用者實際選的項目，沒有自動傳送。以元件測試模擬讀取和預覽請求並驗證；待 CI 與獨立審核後以一般管線部署，無 migration；可回退應用程式 commit。觀察操作錯誤及服務日誌，無新增追蹤個資。

## 參考做法
- W3C ARIA APG checkbox pattern：子項部分勾選時呈現 mixed，Space 操作核取方塊：https://www.w3.org/WAI/ARIA/apg/patterns/checkbox/
- MDN `HTMLInputElement.indeterminate`：使用原生 checkbox 的 JavaScript 屬性反映部分狀態，與 checked 區別：https://developer.mozilla.org/en-US/docs/Web/API/HTMLInputElement/indeterminate
- React Aria Checkbox（Apache-2.0）：以 indeterminate 表示群組部分選取；本改動沿用原生 input，不引入依賴：https://react-spectrum.adobe.com/react-aria/Checkbox.html

## 切換分店的請求生命週期
獨立複審發現原本未結案清單或批次預覽延遲回覆，可能在切換分店後覆蓋新畫面。分店切換時在繪製前清空選取、清單、預覽與編輯對話框，遞增代次使舊請求的成功、錯誤及 finally 都失效；清單同時以每次請求序號避免較慢的舊刷新覆蓋新結果。歷史記錄和單筆預覽沿用現有序號並在切店時失效，歷史深連結也檢查分店代次。A→B→A 不把第一個 A 的回覆當成目前請求。模擬資料測試涵蓋不同分店、延遲成功及錯誤、切店後新預覽仍在載入、返回第一間分店及不自動複製或傳送。
切換時亦清除前店的繳費設定；新店設定未載入時停用複製，避免產生缺漏或前店的匯款資訊。前店設定延遲回覆也須忽略。
切店亦取消尚未確認的對話框；已送出的狀態與訂金更新若遲回，舊店的 rollback、提示和 finally 不得改寫新店畫面。繳費通知按鈕同時只允許一筆送出；舊店回覆不解除新店的進行中狀態。上述網路請求均僅以 mock 驗證，沒有發送 LINE 或操作正式資料。

選取或選取項開始變更時會使仍在產生的舊預覽失效，避免預覽與現況不符。繳費設定載入中、失敗、資料缺欄或無權查看時停用複製，顯示重試；確認設定完成但無付款資料時明示通用話術。後台訂位清單元件對同一訂位的狀態、付款、編輯、還原、刪除與繳費通知，在目前瀏覽器頁面生命週期內共用記憶體鎖，A→B→A 及元件卸載重建也持續鎖定；舊請求結束後先刷新當前列表再開放操作。若請求長時間未完成，需先人工核對。

此鎖不涵蓋其他操作頁面、整頁重載、其他分頁或裝置，並不保證伺服器端冪等。尤其 LINE 請求連線中斷、無法讀回應或伺服器 5xx 時，可能已被平台接受；畫面提示先核對、勿立即重送，沒有自動重送，但目前未實作跨裝置防重或持久不明結果追蹤。狀態及付款 PATCH 的連線中斷同樣不能證明未寫入，提示先重新整理確認；伺服器端版本競態仍須另案處理。
同一分店不同訂位可獨立處理；任何一筆失敗不回寫整張舊清單，而是重新讀取伺服器資料，避免覆蓋另一筆已成功的顯示結果。訂位仍在處理時不得開啟或複製該筆舊訊息；已開啟的預覽會失效。這不保證伺服器在連線中斷後已停止處理。
若重新核對讀取被較新的讀取取代，仍保持「需要成功核對」狀態；最新讀取失敗時不顯示舊資料並提供重試，之後即時背景刷新也先保持載入狀態，直到讀取成功。模擬測試涵蓋一筆失敗、一筆成功及新舊讀取交錯。
編輯、還原、刪除、狀態／訂金更新及手動 LINE 若回應不明或 5xx，先保留該訂位的本頁記憶體待核對鎖；同步重新讀取未結案及已載入歷史清單，不能以舊表單重送。畫面列出訂位碼，要求人工核對後才可解除，並提示原請求仍可能稍後完成。解除前的請求本身不會自動重送。全頁重新載入、不同分頁/裝置或其他 client 無此記憶體鎖；重新讀取或人工解除均不代表伺服器端冪等或保證原請求已停止。
超出歷史篩選範圍、由連結另行載入的指定訂位，在核對開始時清除舊快照及作廢舊請求；核對時若正常清單仍未包含它，必須重新讀取該 id，錯誤或回應不合法就維持 fail-closed。已測修改、刪除、延遲回覆及讀取失敗重試；待確認鎖與其他畫面／裝置仍無共同後端版本。
指定訂位連結的 focus 改變時清除舊 extra row 並關閉舊編輯視窗；有 focus 的即時更新執行完整核對，確認失敗維持 fail-closed。一般無 focus 的即時更新仍使用背景讀取。已以合成資料測試延遲更新及 focus 切換；其他工作站在核對之後才變更仍需倚賴下一次即時通知，不能宣稱伺服器端版本鎖。

即時更新事件到達後，已開啟的相關編輯表單會標示過期並禁止儲存，使用者須重新開啟並核對資料；事件發生期間暫停操作並重新讀取。這依賴事件有成功送達，無法處理斷線、事件尚未送達或其他裝置同時寫入的情況；伺服器尚未提供版本 CAS，不能保證跨裝置寫入不衝突。

# 減少群組空檔訊息

## 根因與範圍

明日提醒在沒有待處理資料或已通知時，原本會額外發送貓咪／狀態訊息。36 小時冷卻仍可能持續消耗配額，而群組每次推播會按可接收的人數計算。這次停止排程的空檔與已通知狀態推播，實際訂位提醒、付款、取消等事件與失敗處理不變。排程執行紀錄仍可透過 `job_runs` 與既有提醒診斷檢視；無訊息不是排程成功證明。

## 參考做法

- LINE 官方 [計費](https://developers.line.biz/en/docs/messaging-api/pricing/) 與 [發送說明](https://developers.line.biz/en/docs/messaging-api/sending-messages/)：push 計入訊息量，群組按可接收人數計算；同一請求最多五個 message objects，計量不因物件數增加。
- Prometheus [Alertmanager](https://github.com/prometheus/alertmanager)（Apache-2.0）支援依接收者分組、去重與靜音。本改動只借鑑降低非必要通知、保留明確觀測的原則，不引入其程式碼或新依賴。
- 根因是固定推送非必要狀態，並非訊息本身字數太多；這不解決大量實際訂位事件、群組成員數或既有併發重送，後續須以官方帳號配額及實際執行記錄判定。

## 驗證與限制

合成測試覆蓋空群組與多分店不推狀態訊息、非空待處理仍推摘要、驗證拒絕請求與既有成功／失敗路徑。未查詢正式帳號餘額、群組成員或資料，也沒有送真 LINE。部署受現有發布暫停及舊版 worker 的切換條件阻擋；無法聲稱目前正式配額節省多少。
